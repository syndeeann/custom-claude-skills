# Data formats

All files live in the site's `data/` folder. The page script `assets/studio.js` reads them; `portfolio_tool.py`
writes them. Edit by hand only when the tool has no command for it.

## studios.json

```json
{ "newBadgeDays": 7, "studios": [
  { "id": "ads", "name": "Ads Videos Studio", "tagline": "...", "description": "...", "path": "ads/",
    "kind": "video", "pipeline": "ads", "icon": "ads", "keywords": ["ad", "tiktok shop", "..."] } ] }
```

- `path` ending in `/` means a generated page at `<path>index.html`. A path ending in `.html` is a hand-built
  page; list it under `legacy_pages` in the profile so `build-pages` leaves it alone.
- `theme` picks the studio's look in `assets/themes.css` (`body[data-theme=...]`: ads, kids and apps exist). `accent` (`R, G, B`) tints its tile on the home page. `fonts` is a Google Fonts query for the page. `badge` and `ticker` are optional hero extras (the ads theme uses both). A new studio needs its own theme block in `themes.css` to look different; without one it gets the default look.
- `kind` is `video` or `app`; it only changes the card layout and the wording.
- `keywords` drive classification when no project rule applies. Multi-word phrases count double.

## videos.json

`{ "items": [ ... ] }`, newest first. One object per delivered video or app:

| field | meaning |
|---|---|
| `id` | unique, `<project>-<topic_id>` |
| `studio`, `project` | studio id; project slug (must exist in `projects.json`) |
| `type` | `video` or `app` |
| `title`, `description` | plain text |
| `published` | `YYYY-MM-DD`, the day it went live. The NEW badge is `0 to newBadgeDays` days after this |
| `duration_s`, `language` | optional |
| `youtube` | 11-character id. The card plays it inline and uses its thumbnail |
| `facebook`, `tiktok`, `instagram`, `link`, `repo` | optional URLs (`link` = live app or watch page, `repo` = source) |
| `platforms` | apps only, e.g. `["Web", "Android"]` |
| `skills` | optional ids; when absent the card shows the studio pipeline's skills |
| `poster`, `src` | optional image and direct video file (relative path or https URL) |

## projects.json

`{ "projects": { "<slug>": { "name": "...", "studio": "stories", "summary": "..." } } }`

## skills.json (generated by `sync-skills`, do not hand-edit)

`{ "repo": URL, "skills": [ { id, name, role, summary, responsibilities[], projects[], category, version, order, url } ] }`
Source of truth is each skill's `metadata` in `SKILL.md`: `title`, `role`, `summary`, `responsibilities` (list),
`projects` (list of slugs), `order`.

## workflow.json

`{ "pipelines": { "<id>": { "title", "intro", "note", "trigger", "run_label", "start_log", "end_log", "claude_does", "i_do", "steps": [ ... ] } } }`
A studio's `pipeline` points at one of these. Each step: `title`, `text`, `tag` (short label such as QUALITY), `log` (line shown when the sample run reaches it), `skills` (ids), `tools` (names). A step can add `warn` and `loop: { "to": step index, "label", "log" }` to show a failed check sending the run back to an earlier step.
The studio page draws these as the same pipeline diagram as the Kwento: Kilabot studio: a snake of step cards joined by wires, a Run button, a run log and a detail panel.

## Hand-built pages

A page with its own design (the Kwento: Kilabot studio) keeps its list of videos between these comments, and
`add` inserts a line there using the template in the profile's `legacy_pages`:

```
/* portfolio-updater:videos:begin */
...
/* portfolio-updater:videos:end */
```
